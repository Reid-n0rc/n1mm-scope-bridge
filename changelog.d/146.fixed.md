The FTDI library folder setting now accepts FTDI's unzipped LibFT4222 package (or any folder inside it) and finds `LibFT4222-64.dll` and `ftd2xx.dll` in their separate package folders for the app's architecture. Choosing DLLs for the wrong processor (for example `arm64` for the x64 app on Windows on ARM) now gives a clear message, and the "Could not load" error names the missing DLL.
The FTDI library folder is now stored and shown in one consistent form: `~` is expanded (a typed `~\Downloads\…` works) and separators follow Windows conventions, including folders chosen with the Browse button.
